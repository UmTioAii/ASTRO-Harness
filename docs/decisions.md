# Decisões arquiteturais (D-xx)

Objetivo: registrar o motivo de cada escolha com ID estável.

| Cobre | Não cobre |
|---|---|
| Decisões D-01 a D-25 do repo e a correspondência com a trilha de planejamento | Invariantes (em `docs/invariants.md`) e ADRs (em `docs/adr/`) |

IDs estáveis; não renumerar.

| ID | Decisão | Contexto / Alternativas | Impacto |
|---|---|---|---|
| D-01 | **Runtime: Bun + TypeScript strict** | Alternativas: Node + tsx, Deno. Bun dá startup rápido, APIs nativas (fetch, WebSocket, SQLite), bundler integrado. | Zero dependências de runtime; `bun test` e `bun run typecheck` são comandos nativos. |
| D-02 | **Zero dependências de runtime** | Apenas stdlib (`node:fs`, `node:path`, `node:crypto`, `node:os`) + Bun globals. Nada de `npm install` para produção. Exceções: Ink/React carregados sob demanda só em `astro tui` (ADR-0001) e o runtime Bun empacotado na distribuição npm (ADR-0017, revisto pelo ADR-0018). | Runtime pinado pela release; binário único no caminho Bun; +~100 MB no install npm. |
| D-03 | **Credencial por cofre local ou env** — segredo repousa no cofre local (`~/.astro/vault.json`, DPAPI no Windows ou 0600) quando há credencial ativa; senão em variável de ambiente nomeada. Codex OAuth continua em `~/.codex/auth.json` (0600). Config nunca guarda valor. | O cofre aceita chave digitada na TUI, permite N credenciais do mesmo provider e rotação sem editar config (ADR-0019). Precedência: cofre ativo > env. | Segredo nunca entra em config, log, audit, ledger, erro ou prompt (I-03); a origem (`vault`/`env`/`ausente`) fica visível sem o valor. |
| D-04 | **Provider abstraction por `kind` discriminado** | `openai-compat` (NVIDIA NIM, OpenRouter) e `codex-oauth`. Interface `Provider` com `complete()`. | Adicionar provider = novo `kind` + factory em `createProvider()`. |
| D-05 | **Model registry com tags de vocabulário fechado (D-17)** | `ROLE_TAGS` (planning, analysis, writing-code…) + `CAPACITY_TAGS` (tools, reasoning, long-context…). Tag desconhecida = config inválida. | Filtro semântico (`registry.list({tags})`), validação estática, evita tag soup. |
| D-06 | **Tool manifest obrigatório (I-12)** | `ToolManifest`: name, description, parameters, risk (low/medium/high), permission, timeoutMs, retryable. | Allowlist por config (I-01), execução negada por default, auditoria de risco. |
| D-07 | **Allowlist por default (I-01)** | `agent.tools` lista nomes permitidos; tool fora da lista não executa. `ToolExecutor` valida contra `allow`. | Superfície de ataque mínima; nova tool exige decisão explícita no PR. |
| D-08 | **Confinamento de caminho ao `cwd` (I-11)** | `resolveFrom(cwd, path)` resolve relativos; `..` e symlinks não escapam. `run_command` herda `cwd`. | Escrita/leitura fora do workspace bloqueada. |
| D-09 | **Auditoria append-only JSONL com sanitização (I-03)** | `Auditor` escreve eventos com `seq`, `ts`, `run`, `tipo`, `payload`. `sanitize()` redige chaves/valores que parecem segredos. | Rastreabilidade total sem vazar credenciais; `seq` garante ordem e detecção de truncamento. |
| D-10 | **Ledger append-only JSONL com custo estimado** | `LedgerEntry`: tokens in/out, `costUsd` (null se sem preço). `estimateCost()` usa `price` curado por modelo. | Custo por run, agregação por provider/modelo, alerta quando `costUsd === null`. |
| D-11 | **Task hash em vez de prompt persistido** | `shortTaskHash(task)` = SHA-256 truncado a 16 chars. Gravado em `run.started.payload.taskHash`. | Correlação de execuções sem persistir dado sensível do usuário. |
| D-12 | **Sessão single-agent com loop de steps** | `runSession`: system prompt → user task → completion → tool calls → repeat até `maxSteps` ou resposta final. | Determinístico, testável, custo controlado por `maxSteps`. |
| D-13 | **Workflow baseado em git worktrees** | `git worktree add .worktrees/<branch> -b <branch> origin/main`. Uma worktree por issue/PR. | Isolamento total; `main` nunca recebe commit direto; rebase fácil. |
| D-14 | **Taxonomia de erros de provider (D-18)** | `ProviderError.errClass`: `transient_rate_limit`, `hard_quota`, `auth`, `outage`, `invalid_request`. | Retry/backoff dirigido; UI pode distinguir "tente depois" de "configure credencial". |
| D-15 | **Config validation com defaults seguros** | `status: "active"` por modelo; `quotaDomain: "default"` por provider; modelo duplicado = erro. | Config mínima viável; falha rápida com mensagem acionável. |
| D-16 | **Squash merge only + linear history** | Branch protection: `allow_squash_merge=true`, `allow_merge_commit=false`, `allow_rebase_merge=false`, `required_linear_history=true`. | Histórico limpo; cada PR = um commit atômico com `Closes #n`. |
| D-17 | **Vocabulário fechado de tags** (ver D-05) | Duas listas imutáveis em `src/tags.ts`. Validação em `validateModel()`. | Extensão controlada via PR + ADR; sem typos silenciosos. |
| D-18 | **Taxonomia de erros** (ver D-14) | `ErrorClass` type + `ProviderError` class. Usado em `openai-compat.ts`, `codex-oauth.ts`. | Tratamento uniforme; logs e métricas por classe. |
| D-19 | **Ciclo de vida de modelo** | `ModelStatus`: `active` | `deprecated` | `disabled`. `Registry.require()` só devolve `active`. | Descontinuação segura; modelos legados ficam na config mas não são selecionáveis. |
| D-20 | **Quota domain por provider** | `quotaDomain` agrupa credenciais que compartilham limite (ex.: mesma conta OpenRouter). Default `"default"`. | Ledger e futuras quotas operam no domínio correto. |
| D-21 | **Perfis globais de provider** | `~/.astro/providers.json` (`ASTRO_HOME`) guarda perfis sem segredo; projeto vence por nome; ativo segue `--provider` > `ASTRO_PROVIDER` > `activeProfileId` > `agent.model`; env é efêmero e a baseline sem config é somente leitura. | CRUD pelo `/provider` e onboarding sem editar JSON (#201); a origem fica auditada em `run.started`. |
| D-22 | **Contagem de tokens por provider** | Pura e determinística: tokenizer nativo registrado por provider; senão estimativa documentada de 4 chars/token; resultado marcado `measured`/`estimate` e nunca zero para texto não vazio. `src/tokens.ts`. | Compaction (S-17) e overflow retry usam a mesma contagem; sem chamada de provider e sem segredo (I-03). |
| D-23 | **`cache.ttlHours = 0` desliga o cache** | Antes TTL zero significava "nunca expira", o oposto de quem quer desligar. `enabled: false` continua sendo o jeito declarativo; `ttlHours: 0` zera leitura e escrita. | `cachedProvider` devolve o provider puro e `CompletionCache.get` devolve `null`; config mantém `ttlHours >= 0`. |
| D-24 | **Modos de permissão por chamada** | `bypass`/`allow-edits`/`ask`, default `ask`, resolvidos depois do allowlist; troca de identidade pede aprovação em todos os modos, inclusive `bypass`. `--permission-mode` vence a config (#269). | `src/permissions.ts` e gate no executor com evento `permission.decision`; `.astro/`/`protectedPaths`, redação e cwd são piso fixo. `ask` sem TTY (CLI não interativa) nega com `permission.pending` e para (#262); grants `once`/`session` ficam só em memória (`PermissionGrants`), nunca no disco (#266); com TTY, TUI e REPL perguntam na hora com 4 opções — `s` aprova, `n` nega, `S` aprova nesta sessão, `o` só esta vez — via `chatApprovers`/`createApprovalBridge` (#265); na TUI o modo ativo fica sempre visível no banner e no footer, em cor de alerta quando `bypass` (#270); `/mode [modo]` no REPL e na TUI lista os modos e troca em runtime — entrar em `bypass` exige `/mode bypass confirm`, a troca é auditada (`mode.changed`) e o próximo turno já usa o modo novo (#271); `/config` abre a tela cheia de configuração na TUI (e imprime o resumo no REPL) — mostra `run.maxTurns`, custos por modelo (`pricing` vence `model.price`), `permissions.mode`, budget e pastas confiáveis — e trocar o modo na tela persiste em `astro.config.json` via `updateConfigPermissionsMode` (escrita atômica validada, arquivo intacto em caso de erro) antes de aplicar na sessão (#273); `/usage` no REPL e na TUI imprime uso da sessão (turnos, tokens, custo — `n/d` quando o preço falta, B6) e a linha de budget derivada do ledger (`src/chat/usage.ts`), e o footer da TUI mostra o segmento curto de budget em cor de alerta quando aviso/esgotado/teto (#63); o editor da TUI é multi-linha — `enter` envia, `shift+enter` (kitty `CSI 13;2u` ou linefeed legado `\n`) quebra linha, com dica visível sob a caixa — e texto multi-linha nunca é interpretado como comando de barra (#63); toasts não bloqueantes mostram erro, conclusão de turno, aviso de custo alto do budget e aviso de quota por domínio (F6-3) por alguns segundos (`src/tui/toasts.ts`, fila com TTL e teto), sem bloquear a entrada, enquanto o histórico em `<Static>` continua permanente (#64); `/theme [dark|light|contrast]` lista/troca o tema na TUI (persistido em `.astro/tui.json`, aplicado sem reiniciar; `ctrl+x t` cicla os três) e no REPL avisa que o tema é da TUI — o tema `contrast` usa cores brilhantes de alto contraste (#64); `/sessions` na TUI abre um modal para listar, renomear (`SessionStore.rename` grava o nome no próprio arquivo da sessão, atômico e sem duplicar, e o auto-save o preserva) e retomar sessões, enquanto o REPL segue listando em texto (#64). |
| D-25 | **Confirmação humana pelo approval bridge, sem `ask_user` model-facing** | O gate é da UI/camada de permissão: `src/permissions.ts` (classe de ação), `src/tui/approvals.ts` (linha de aprovação), `src/approval.ts`/`src/chat/approvers.ts` (troca, I-08) e `src/budget.ts` (orçamento). Pergunta que não é de permissão é prompt da TUI do comando que a precisa, não tool. | Não dá ao modelo canal de interrogatório fora da decisão de permissão; preserva I-18 e I-19; T2 (#63) consome o approval bridge sem allowlist, manifesto ou audit novo (#306). Se surgir pergunta livre real, exige tool própria com manifesto, allowlist e parada I-19, e ADR novo. |
| D-26 | **Trust por pasta persistido fora do projeto** | 1º open de um cwd não confiável pergunta no TTY (TUI/REPL/CLI) e a resposta grava em `$ASTRO_HOME/trusted.json` ou `~/.astro/trusted.json` (save atômico 0600, validação estrita que cita só o caminho — I-03); subpasta herda a confiança da ancestral; negar joga `TrustDeniedError` e para o run (I-19); revogação fica para o `/config` (#273). Sem TTY (eval/CI) o run prossegue sem persistir nada (#267). | `src/trust.ts` (`TrustedFolders`/`ensureTrustedCwd`) ligado no `runTask` via `trustAsk` injetável, audit `trust.decision` com `{folder, decision}`; store sem segredo, erro de store corrompido cita o caminho e nunca o conteúdo. |
| D-27 | **Checkpoint e guarda de não-progresso ligados no loop** | L5/L6 (ADR-0014, #135): ao atingir `run.checkpointAt` do limite de turnos **ou** do gasto do escopo do budget (ledger; não só o run atual), o run grava **uma vez** `checkpoint/v1` em `.astro/sessions/<run>/<agent>/checkpoint.json` (save atômico 0600, resumo com `redactSecrets` I-03, só arquivos dentro do cwd como caminho relativo I-11; audit `loop.checkpoint`; continuar é `astro resume` com o limite elevado, e subir budget segue o decisor B4); `run.noProgressSegments` segmentos consecutivos com o mesmo hash (sha256 dos arquivos tocados pelas tools + nº de erros) disparam audit `loop.no_progress` e a pergunta via `onNoProgress` — continuar reseta a sequência, negar/sem decider joga `NoProgressError` (`no_progress`, I-19). CLI run/resume/replay perguntam no TTY; chat/TUI não passam decider e param seguro. | `src/loop-guard.ts` (puro + persistência) fiado em `runSession` (`src/session.ts`) via `SessionOptions.checkpointAt/noProgressSegments/onNoProgress`, que o `runTask` (`src/app.ts`) preenche de `config.run`; `interruptReason` mapeia `no_progress` no estado `interrupted`. |
| D-28 | **Perfis de permissão de agente** | `agents.<nome>.permission` é `read-only`/`write`/`execute`/`full` (ausente = `full` para compatibilidade); compõe com a allowlist (I-01) — a mais restritiva vence. `read-only` só lê; `write` adiciona edit/delete; `execute` adiciona shell; `full` permite tudo. `handoff` exige `full` e `spawn_agent` exige `execute`. Negação gera `tool.denied` com `{name, reason, required, permission}`. | `src/permissions.ts` (`requiredPermission`/`permissionAllows`) e gate no `ToolExecutor`; `runMultiAgentSession` recria o executor por agente com o perfil corrente (#58). |
